给合成制品的安全发布做 splitrelease。我们有两组不同步的不可变记录：一组存产物摘要及构建依赖，另一组存审批回执、人员别名变动和临时吊销。发布时有一个确认过的双向检查点，分别锁定两个源的前缀。只要已给先后约束未违反，检查点后的事件可以按任一合法顺序抵达。每个候选制品要在所有合法顺序下都从两个不同独立审批组拿到绑定同一依赖闭包摘要的有效票，并且有效票数达到当前阶段阈值。审批关联的是摘要和有效的自然人，组名相同和标签移动不视为同一对象。
做 certify CASE 给每个发布候选判定一定可发布、一定不可、或取决于顺序，后者至少给一条通过和一条拒绝的完整可复核前缀。确定通过时给能排除所有反例的最小日志证据集合，证据允许保留因果前驱，并以条数和 ID 决胜。做 protect，从 16 个拟议暂停点中选最少总停工时间，防止任意不确定候选被提交且所有必办合规制品仍可发布。样例必须有两个独立的撤销先后组合，单独看每条都过而组合会失败。普通日志十万条，只有有歧义的窗口最多 16 个事件；附小例全拓扑序对拍，不能拿文件行序作因果证据。
从空仓库实现，使用 Windows 普通 CPU 和 Python 3.12 标准库，全部离线。交付 UTF-8 JSON CLI、明确的输入格式、README、合成夹具及 unittest。
